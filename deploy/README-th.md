# ติดตั้ง Helpdesk บน Windows Server (SQL Server)

คู่มือนี้สำหรับฝ่าย IT ของบริษัทที่จะติดตั้ง Helpdesk ในเครือข่ายภายใน ใช้ SQL Server เป็นฐานข้อมูล
**ไม่ต้องใช้ IIS และไม่ต้องใช้ Docker** โปรแกรมเดียวทำทั้งหน้าเว็บและ API และรันเป็น Windows Service

## สิ่งที่ต้องมี

| รายการ | รายละเอียด |
|---|---|
| เซิร์ฟเวอร์ | Windows Server 2016 ขึ้นไป (หรือ Windows 10/11) 64 บิต ไม่ต้องติดตั้ง .NET เพราะมากับชุดติดตั้งแล้ว |
| SQL Server | 2017 ขึ้นไป รุ่นใดก็ได้ (Express ใช้ได้) ที่เครื่องนี้หรือเครื่องอื่นที่เข้าถึงได้ เปิดโปรโตคอล TCP/IP แล้ว (ถ้าจะใช้ `sa` ต้องเปิดโหมด "SQL Server and Windows Authentication" และเปิดใช้งานบัญชี `sa`) |
| บัญชีที่สร้างฐานข้อมูลได้ | เช่น `sa` หรือบัญชีที่เป็น sysadmin ใช้ **ครั้งเดียวตอนเชื่อมต่อ** ไม่ถูกบันทึก (ถ้าจะสร้างฐานข้อมูลไว้เองก่อน ใช้บัญชีที่เปิดฐานข้อมูลนั้นได้ก็พอ) |
| พอร์ต | ค่าเริ่มต้น 8080 (เปลี่ยนได้) |
| อีเมลขาออก | ตั้งในหน้าตั้งค่าของแอปภายหลัง (SMTP ขององค์กรเรียกใช้ได้เพราะเซิร์ฟเวอร์อยู่ในเครือข่ายเดียวกัน) |

ไม่ต้องมี `sqlcmd` และไม่ต้องรันสคริปต์ SQL เอง (ยกเว้นเลือกวิธี `-WithDatabase` ด้านล่าง)

## ขั้นที่ 1: ติดตั้งโปรแกรม

1. แตกไฟล์ `helpdesk-server-<เวอร์ชัน>.zip` ไว้ที่เซิร์ฟเวอร์ เช่น `C:\Temp\helpdesk-server`
2. เปิด PowerShell แบบ **Run as administrator** ไปที่โฟลเดอร์นั้น แล้วรัน

   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   .\install.ps1 -PublicUrl http://helpdesk01:8080 -OpenFirewall
   ```

   สคริปต์ถามเฉพาะชื่อบริษัทกับที่อยู่ที่ผู้ใช้จะใช้เปิด Helpdesk (ถ้าไม่ได้ใส่เป็นพารามิเตอร์) **ไม่ถามเรื่อง SQL Server**
3. สคริปต์คัดลอกโปรแกรมไป `C:\Helpdesk\api` เขียนไฟล์ตั้งค่า `appsettings.Production.json` (คีย์เซ็น token สร้างสุ่มให้ ไฟล์อ่านได้เฉพาะ Administrators และ service) สร้างโฟลเดอร์ `C:\Helpdesk\data` สำหรับสิ่งที่โปรแกรมเขียนเอง (ค่าการเชื่อมต่อฐานข้อมูล ไม่ถูกแตะตอนอัปเดต) แล้วติดตั้งและเริ่ม Windows Service ชื่อ `Helpdesk` (เริ่มเองเมื่อเปิดเครื่อง และเริ่มใหม่เองถ้าล้ม)

ดูพารามิเตอร์ทั้งหมดด้วย `Get-Help .\install.ps1 -Full`

## ขั้นที่ 2: เชื่อมต่อฐานข้อมูล (ในแอป)

1. บนเครื่องเซิร์ฟเวอร์ เปิดเบราว์เซอร์ไปที่ `http://localhost:8080` หน้าเข้าสู่ระบบจะแจ้งว่ายังไม่ได้เชื่อมต่อฐานข้อมูล และเปิดหน้าต่าง **เชื่อมต่อฐานข้อมูล** ให้ (เปิดเองได้ที่ปุ่ม **เชื่อมต่อ** บนแถบด้านบนของหน้า มีแท็บ **ประวัติ** สำหรับเลือกเซิร์ฟเวอร์ที่เคยเชื่อมต่อ ไม่เก็บรหัสผ่าน)
2. กรอก **เซิร์ฟเวอร์ SQL** (เช่น `SQL01`, `SQL01\SQLEXPRESS`, `10.0.0.5,1433`) ชื่อผู้ใช้ `sa` รหัสผ่าน และชื่อฐานข้อมูล (ค่าเริ่มต้น `helpdesk`) แล้วกด **เชื่อมต่อ**
3. ระบบบอกทันทีว่า
   - เชื่อมต่อ SQL Server ได้หรือไม่ (ถ้าไม่ได้ บอกสาเหตุ: เซิร์ฟเวอร์ไม่ตอบ / ล็อกอินไม่ผ่าน)
   - **มีฐานข้อมูลนี้อยู่แล้วหรือยัง** ถ้ายังไม่มี จะสร้างให้ ถ้ามีแล้ว **จะไม่สร้างใหม่** และแสดงรายการตรวจว่าขาดตารางหรือข้อมูลตั้งต้นอะไร
   - บัญชีที่ใช้กดเริ่มได้หรือไม่ (ต้องสร้างฐานข้อมูลและบัญชีได้ ถ้าไม่พอ บอกว่าขาดสิทธิ์อะไร)
4. กรอกผู้ดูแลระบบคนแรก (เฉพาะเมื่อฐานข้อมูลนี้ยังไม่มีผู้ดูแล) แล้วกด **สร้างฐานข้อมูลและเริ่มระบบ** ระบบทำตามลำดับ: สร้างฐานข้อมูล (ถ้ายังไม่มี เรียงลำดับตัวอักษรแบบไม่สนตัวพิมพ์ ซึ่งจำเป็น เพราะอีเมลต้องไม่ซ้ำไม่ว่าตัวพิมพ์เล็กใหญ่) → สร้างบัญชีของเครื่องนี้ → สร้างตารางและข้อมูลตั้งต้น (บทบาทและสิทธิ์) → สร้างผู้ดูแลระบบ → จำค่าไว้ แล้วเริ่มทำงานทันทีโดยไม่ต้องรีสตาร์ต service และพาไปหน้าเข้าสู่ระบบ

### บัญชีที่โปรแกรมใช้เชื่อมต่อ

- **ค่าเริ่มต้น (แนะนำ):** ระบบสร้างบัญชี SQL ให้เครื่องนี้โดยเฉพาะ ชื่อ `helpdesk_<ชื่อเครื่อง>` (แก้ชื่อได้ใน "ตัวเลือกเพิ่มเติม") พร้อมรหัสผ่านสุ่ม บัญชีนี้เป็นเจ้าของฐานข้อมูลนี้ฐานข้อมูลเดียว ไม่มีสิทธิ์บนส่วนอื่นของเซิร์ฟเวอร์ และรหัสผ่านไม่หมดอายุ **รหัสผ่าน `sa` ใช้ครั้งเดียวและไม่ถูกบันทึก** ไฟล์ตั้งค่าเก็บเฉพาะบัญชีของเครื่องนี้ (รหัสผ่านเข้ารหัสด้วยคีย์ของเซิร์ฟเวอร์) ถ้าเครื่องไหนหลุด เพิกถอนทีละเครื่องด้วย `DROP LOGIN`
- **ใช้บัญชีที่กรอกต่อเลย:** ติ๊ก "ใช้บัญชี ... เป็นบัญชีของโปรแกรมด้วย" ง่ายกว่า แต่ไม่แนะนำ เพราะโปรแกรมจะมีสิทธิ์ทั้งเซิร์ฟเวอร์ ถ้ารหัสนี้รั่วจะเสียหายกว่า
- **บัญชี Windows:** เลือก "บัญชี Windows ที่ service ใช้อยู่" ไม่มีรหัสผ่านฐานข้อมูลในไฟล์ตั้งค่า (SQL Server อยู่เครื่องเดียวกันใช้ `NT SERVICE\Helpdesk` ได้ อยู่คนละเครื่องให้ service รันด้วยบัญชีโดเมน)

### เครื่องที่สอง สาม ... ในเครือข่ายเดียวกัน

ติดตั้งโปรแกรม (ขั้นที่ 1) บนแต่ละเครื่อง แล้วทำขั้นที่ 2 **เหมือนกันทุกเครื่อง** กรอก SQL Server และรหัสผ่านเดียวกัน ชื่อฐานข้อมูลเดียวกัน
เครื่องแรกสร้างฐานข้อมูล เครื่องถัดไปจะเห็นว่า **ฐานข้อมูลมีอยู่แล้ว** และ **ไม่สร้างใหม่** (ไม่แตะตารางหรือข้อมูลเดิม) แค่ได้บัญชีเชื่อมต่อของตัวเอง และไม่ต้องสร้างผู้ดูแลระบบอีก (ใช้ผู้ดูแลเดิม)
ถ้ากดพร้อมกันหลายเครื่อง ฐานข้อมูลถูกสร้างเพียงครั้งเดียว

ข้อควรรู้เมื่อใช้หลายเครื่อง
- ทุกเครื่องใช้ข้อมูลชุดเดียวกัน แต่ **การแจ้งเตือนสดข้ามเครื่องไม่ถึงกัน** (ผู้ใช้ที่เปิดคนละเครื่องจะเห็นการเปลี่ยนแปลงของอีกเครื่องเมื่อรีเฟรช) เพราะการแจ้งเตือนสดทำงานภายในเครื่องแต่ละเครื่อง ยังไม่มีตัวกลางเชื่อมระหว่างเครื่อง
- ค่าในหน้าตั้งค่าระบบที่แก้บนเครื่องหนึ่ง อีกเครื่องรับค่าใหม่ภายใน 1 นาที
- **ทุกเครื่องควรใช้ `Jwt:Key` เดียวกัน** ข้อมูลที่เก็บแบบเข้ารหัสในฐานข้อมูล (เช่นรหัสผ่านอีเมลในหน้าตั้งค่า) อ่านได้เฉพาะเครื่องที่มีคีย์เดียวกัน และ token การเข้าสู่ระบบของเครื่องหนึ่งใช้กับอีกเครื่องไม่ได้ ติดตั้งเครื่องแรกแล้วคัดลอกค่า `Jwt.Key` จากไฟล์ `C:\Helpdesk\api\appsettings.Production.json` ไปใส่ตอนติดตั้งเครื่องอื่น: `.\install.ps1 -JwtKey (Read-Host -AsSecureString)` (ต้องยาวอย่างน้อย 32 ตัวอักษร) ถ้าไม่ได้ทำ เครื่องอื่นจะอ่านรหัสผ่านอีเมลที่ตั้งไว้ไม่ได้ ต้องกรอกใหม่บนเครื่องนั้น
- เมื่ออัปเดตโปรแกรม ให้อัปเดตทุกเครื่องในช่วงเวลาใกล้กัน เครื่องแรกที่เริ่มด้วยรุ่นใหม่จะปรับโครงสร้างตารางของฐานข้อมูลที่ใช้ร่วมกัน ระหว่างนั้นเครื่องที่ยังเป็นรุ่นเก่าอาจทำงานผิดพลาดจนกว่าจะอัปเดต
- เครื่องสองเครื่องที่ชื่อเครื่องเหมือนกันจะได้ชื่อบัญชีเดียวกัน ถ้าชื่อนั้นมีอยู่แล้ว ระบบตั้งรหัสผ่านใหม่ให้ ทำให้เครื่องแรกต่อไม่ได้เมื่อรีสตาร์ต ให้ตั้งชื่อบัญชีใน "ตัวเลือกเพิ่มเติม" ไม่ให้ซ้ำกัน

## วิธีอื่น: ให้สคริปต์ทำเอง (`-WithDatabase`)

ถ้าอยากให้สคริปต์ติดตั้งสร้างฐานข้อมูลและผู้ดูแลคนแรกให้เลย (ต้องมี `sqlcmd`: "Microsoft SQL Server command line utilities") หรืออยากสร้างด้วยสคริปต์ SQL เอง

```powershell
.\install.ps1 -WithDatabase -SqlServer SQL01 -Database helpdesk -PublicUrl http://helpdesk01:8080 -OpenFirewall
```

สคริปต์ถามอีเมล/ชื่อ/รหัสผ่านของผู้ดูแลคนแรก แล้วทำตามลำดับ
1. สร้างฐานข้อมูลและบัญชีที่แอปใช้เชื่อมต่อ (`sqlserver\01-create-database.sql`)
2. สร้างตาราง (`02-schema.sql`)
3. ใส่บทบาทและสิทธิ์ตั้งต้น (`03-seed.sql`)
4. สร้างผู้ดูแลคนแรก และติดตั้ง service

สคริปต์ทั้งสามไฟล์รันซ้ำได้ ไม่ทำลายข้อมูลเดิม ถ้าอยากรันเองให้ใช้ `sqlcmd` (หัวไฟล์มีคำอธิบาย) หรือใน SQL Server Management Studio (SSMS): เปิดไฟล์ เปิดโหมด **Query → SQLCMD Mode** ใส่บรรทัด `:setvar` สี่บรรทัด (`DbName`, `AuthMode`, `AppLogin`, `AppPassword`) ไว้บนสุดตามตัวอย่างที่หัวไฟล์ แล้วกด Execute
ตัวเลือกบัญชี: `-AppAuth Sql` (ค่าเริ่มต้น สร้าง login `helpdesk_<ชื่อเครื่อง>` เหมือนที่แอปทำ ถ้ามี login ชื่อนี้อยู่แล้ว สคริปต์ตั้งรหัสผ่านของ login นั้นใหม่ให้ตรงกับที่บันทึกในไฟล์ตั้งค่า และไม่แตะ login ที่เป็น sysadmin) หรือ `-AppAuth Windows` (เช่น `-AppLogin 'CORP\svc-helpdesk' -ServiceAccount 'CORP\svc-helpdesk'`)
แอปเองก็สร้าง/อัปเดตตารางให้เมื่อเริ่มทำงาน (ปิดได้ด้วย `Database:AutoMigrate = false` ถ้าต้องการรันสคริปต์เองทุกครั้ง)

ค่าที่เชื่อมต่อในแอปถูกเก็บใน `C:\Helpdesk\data\database.json` ไฟล์นี้ชนะค่าอื่นทุกแหล่ง และอยู่รอดตอนอัปเดต (`-Upgrade` ไม่แตะโฟลเดอร์ `data`)

### ถ้าเชื่อมต่อฐานข้อมูลไม่ได้ในภายหลัง

ตอนที่ service เริ่มทำงาน (เปิดเครื่องใหม่หรือรีสตาร์ต) ถ้าเซิร์ฟเวอร์ SQL ปิด รหัสผ่านถูกเปลี่ยน หรือฐานข้อมูลถูกลบ service จะ **ไม่ล้ม** แต่แสดงหน้าเข้าสู่ระบบพร้อมปุ่มเชื่อมต่อฐานข้อมูล และลองเชื่อมใหม่เองทุก 10 วินาที
เมื่อแก้ฝั่ง SQL Server แล้วระบบกลับมาทำงานเอง หรือจะกรอกที่อยู่ใหม่ในหน้าต่างเชื่อมต่อก็ได้
ถ้าปัญหาเกิดตอนที่ระบบทำงานอยู่แล้ว ระบบจะต่อฐานข้อมูลใหม่เองเมื่อเซิร์ฟเวอร์ SQL กลับมา แต่ถ้ารหัสผ่านของบัญชีที่ใช้ถูกเปลี่ยน ให้รีสตาร์ต service เพื่อเข้าหน้าต่างเชื่อมต่อ
ถ้าไฟล์ `database.json` ถูกแก้ด้วยมือจนอ่านไม่ได้ โปรแกรมจะข้ามไฟล์นั้น (และบันทึกข้อความไว้ใน log) แล้วแสดงหน้าต่างเชื่อมต่อ
เมื่อระบบทำงานอยู่แล้ว ใช้ **ตั้งค่า → ฐานข้อมูล** ตรวจว่าขาดตารางหรือคอลัมน์อะไร และกดซ่อมได้

### ความปลอดภัยของการเชื่อมต่อฐานข้อมูลในแอป

- หน้าต่างนี้ทดสอบและบันทึกได้ **เฉพาะจากเครื่องเซิร์ฟเวอร์เอง** (`localhost`) ซึ่งไม่ต้องใช้รหัสตั้งค่า เพราะผู้ที่เปิดเว็บบนเครื่องเซิร์ฟเวอร์ได้ถือว่าดูแลเครื่องอยู่แล้ว เครื่องอื่นเห็นได้แค่ว่ากำลังรอตั้งค่า (ไม่เห็นชื่อเซิร์ฟเวอร์ ผู้ใช้ หรือที่เก็บรหัส)
- อยากให้ถามรหัสแม้บนเครื่องเซิร์ฟเวอร์ ตั้ง `Setup:Key` (อย่างน้อย 8 ตัวอักษร) ใน `appsettings.Production.json` แล้วหน้าต่างจะมีช่องรหัสตั้งค่า ใส่ผิด 10 ครั้งจะถูกล็อก 10 นาที
- ถ้าจำเป็นต้องตั้งจากเครื่องอื่นจริง ๆ ใส่ `Setup:AllowRemote=true` ชั่วคราว ระบบจะสร้างรหัสตั้งค่าให้ที่ `C:\Helpdesk\data\setup-key.txt` (เฉพาะ Administrators) และบังคับให้ใส่เมื่อเปิดจากเครื่องอื่น ไม่แนะนำ เพราะรหัสผ่าน `sa` จะวิ่งผ่านเครือข่ายแบบ HTTP
- **ถ้ามี reverse proxy อยู่หน้า ให้ตั้ง `Setup:Key` เสมอ** (หรือปิดด้วย `Setup:Enabled=false` ซึ่งโปรแกรมจะทำงานแบบเดิม คือหยุดถ้าเชื่อมฐานข้อมูลไม่ได้) เพราะหน้าเชื่อมต่อไม่ได้เกิดเฉพาะตอนติดตั้ง ทุกครั้งที่ service เริ่มและ SQL Server ยังไม่ตอบภายใน 45 วินาที (เช่นเปิดเครื่องพร้อมกัน) โปรแกรมจะกลับมาที่หน้านี้ และคำขอที่ผ่าน proxy ในเครื่องเดียวกันดูเหมือนมาจาก localhost โปรแกรมตรวจเท่าที่ทำได้ (ปฏิเสธคำขอที่มี header `X-Forwarded-*`, `Forwarded`, `X-Real-IP` หรือที่ส่งถึงชื่ออื่นนอกจาก localhost) แต่ proxy ที่ไม่ใส่ header เหล่านี้และตั้ง Host เป็น localhost ตรวจไม่ได้
- คำขอจากหน้าเว็บของเว็บไซต์อื่น (เช่นหน้าที่เปิดในเบราว์เซอร์บนเครื่องเซิร์ฟเวอร์) ถูกปฏิเสธเสมอ
- เชื่อมต่อแบบไม่ใช้หน้าเว็บก็ได้ เรียก API บนเครื่องเซิร์ฟเวอร์ (ใช้ `/api/setup/test` กับ `connection` อย่างเดียวถ้าแค่อยากตรวจโดยไม่เปลี่ยนอะไร ถ้าตั้ง `Setup:Key` ให้ส่ง header `X-Setup-Key`)

  ```powershell
  $body = @{
      connection = @{ server = 'SQL01'; database = 'helpdesk'; auth = 'sql'; user = 'sa'; password = '<รหัสผ่าน sa>'; trust = $true }
      repair     = @{ applyMigrations = $true; createMissingObjects = $true; seed = $true }
      admin      = @{ email = 'admin@company.th'; firstName = 'Admin'; lastName = ''; password = '<รหัสผ่านผู้ดูแล>' }
  } | ConvertTo-Json -Depth 5
  Invoke-RestMethod http://localhost:8080/api/setup/apply -Method Post -ContentType 'application/json' -Body $body
  ```

## หลังติดตั้ง

- เปิด URL ของ Helpdesk ล็อกอินด้วยผู้ดูแลที่สร้างไว้
- **ตั้งค่า → ตั้งค่าระบบ → องค์กร** ชื่อบริษัทที่ตอบตอนติดตั้ง (`-CompanyName`) จะแสดงบนหน้าเข้าสู่ระบบ แถบด้านข้าง และชื่อหน้าต่าง เปลี่ยนได้ที่นี่โดยไม่ต้องรีสตาร์ต ถ้าลบออกจะกลับไปใช้ชื่อที่ตั้งตอนติดตั้ง
- **ตั้งค่า → อีเมล (SMTP)** ใส่เซิร์ฟเวอร์ พอร์ต ผู้ใช้ รหัสผ่าน แล้วกด "ส่งอีเมลทดสอบ"
- **ตั้งค่า → ความปลอดภัย** ปรับนโยบายรหัสผ่านตามที่บริษัทต้องการ
- **ตั้งค่า → ผู้ใช้งาน / แผนก / บทบาทและสิทธิ์** เพิ่มคนและกำหนดสิทธิ์
- เปิด firewall ให้พอร์ตของ Helpdesk (`-OpenFirewall` ตอนติดตั้ง หรือ `New-NetFirewallRule` เอง)

## แอป Windows (.exe) ที่ใช้กับเซิร์ฟเวอร์นี้

แอปติดตั้งมาชี้ไปที่เซิร์ฟเวอร์กลางของผู้พัฒนา ต้องบอกให้ใช้เซิร์ฟเวอร์ของบริษัทคุณ มี 2 วิธี

1. **ให้ผู้ใช้เลือกเอง:** ที่หน้าเข้าสู่ระบบกด "เปลี่ยน" ข้าง "เซิร์ฟเวอร์" ใส่ที่อยู่ (เช่น `http://helpdesk.company.local:8080`) กด "ทดสอบ" แล้วกด "ใช้เซิร์ฟเวอร์นี้" แอปจำค่านี้ไว้ในเครื่อง และเปลี่ยนใหม่ได้ที่ ตั้งค่า → เกี่ยวกับ
2. **ให้ IT ตั้งให้ทั้งเครื่อง (แนะนำ ผู้ใช้ไม่ต้องทำอะไร):** สร้างไฟล์ `C:\ProgramData\Helpdesk\server.txt` บรรทัดแรกเป็นที่อยู่เซิร์ฟเวอร์ หรือตั้งตัวแปรสภาพแวดล้อม `HELPDESK_SERVER_URL` ไฟล์นี้ไม่หายเมื่อแอปอัปเดต และผู้ใช้ยังเปลี่ยนเองภายหลังได้

ที่อยู่ต้องเป็นรูป `http(s)://ชื่อเซิร์ฟเวอร์[:พอร์ต]` ไม่มีเส้นทางต่อท้าย
- ใช้ `http` ได้ในเครือข่ายภายใน แต่ข้อมูลรวมถึงรหัสผ่านไม่ถูกเข้ารหัส แอปจึงเตือนทุกครั้ง
- ใช้ `https` ได้ถ้าเครื่องผู้ใช้เชื่อถือใบรับรอง (ใบรับรององค์กรที่ติดตั้งใน Windows แล้วใช้ได้)
- เซิร์ฟเวอร์อนุญาตให้แอปนี้เชื่อมต่อได้อยู่แล้วตามค่าเริ่มต้น ส่วนผู้ที่เปิดผ่านเบราว์เซอร์ใช้ที่อยู่ `-PublicUrl` ที่ตั้งตอนติดตั้ง

## HTTPS

โปรแกรมเปิดพอร์ต HTTP ธรรมดา ถ้าผู้ใช้เข้าผ่านเครือข่ายที่ไม่ปลอดภัย หรือบริษัทกำหนดให้ใช้ HTTPS ทำอย่างใดอย่างหนึ่ง

1. **ใส่ reverse proxy หน้าโปรแกรม** (IIS + ARR, nginx, Caddy หรืออุปกรณ์ของบริษัท) ให้ proxy ถือใบรับรอง แล้วส่งต่อมาที่ `http://localhost:8080` ต้องเปิดรองรับ WebSocket (การแจ้งเตือนสดใช้) และตั้ง `-PublicUrl` เป็นที่อยู่ https ของ proxy
2. **ให้โปรแกรมใช้ใบรับรองเอง** เพิ่มใน `appsettings.Production.json`
   ```json
   "Kestrel": { "Endpoints": { "Https": { "Url": "https://0.0.0.0:8443", "Certificate": { "Path": "C:\\certs\\helpdesk.pfx", "Password": "..." } } } }
   ```
   แล้วรีสตาร์ต service (และแก้ `Urls`/`Cors:Origins`/`App:BaseUrl` ให้ตรง)

ถ้ามี proxy อยู่หน้า โปรแกรมต้องรู้ IP จริงของผู้ใช้ (สำหรับบันทึกและตัวหน่วงการเดารหัส) ตั้ง `LoginThrottle:ClientIpHeader` เป็นชื่อ header ที่ proxy ใส่ เช่น `X-Forwarded-For` **ตั้งเฉพาะเมื่อทุกคำขอผ่าน proxy จริง** ไม่เช่นนั้นผู้ใช้ปลอม header ได้

## อัปเดตเป็นรุ่นใหม่

แตกชุดติดตั้งรุ่นใหม่ แล้วรันใน PowerShell (administrator)

```powershell
.\install.ps1 -Upgrade
```

สคริปต์หยุด service, เก็บโปรแกรมเดิมไว้ที่ `C:\Helpdesk\api.backup-<เวลา>` (ไฟล์ตั้งค่าในนั้นอ่านได้เฉพาะ Administrators เหมือนไฟล์จริง ลบโฟลเดอร์สำรองเมื่อไม่ต้องการแล้ว), ใส่ไฟล์ใหม่, เก็บไฟล์ตั้งค่าเดิมไว้เหมือนเดิม แล้วเริ่ม service ใหม่ ตารางในฐานข้อมูลอัปเดตเองตอนเริ่ม
**สำรองฐานข้อมูลก่อนอัปเดตเสมอ**

## สำรองและกู้คืน

- **สำรอง:** สำรองฐานข้อมูลของ Helpdesk ตามปกติของ SQL Server (`BACKUP DATABASE helpdesk TO DISK = '...'` หรือ Maintenance Plan) ไฟล์แนบ (รูป) **เก็บอยู่ในฐานข้อมูล** จึงอยู่ในไฟล์สำรองเดียวกัน
- **สำรองไฟล์ตั้งค่า** `C:\Helpdesk\api\appsettings.Production.json` และโฟลเดอร์ `C:\Helpdesk\data` ไว้ที่ปลอดภัย (มีคีย์เซ็น token ถ้าหายต้องให้ทุกคนล็อกอินใหม่ และรหัสผ่านอีเมลที่เก็บในระบบจะอ่านไม่ได้ ต้องกรอกใหม่)

## ถอนการติดตั้ง

```powershell
Stop-Service Helpdesk; sc.exe delete Helpdesk
Remove-Item C:\Helpdesk -Recurse
```
ฐานข้อมูลไม่ถูกลบ ถ้าต้องการให้ลบเองใน SQL Server (`DROP DATABASE`, `DROP LOGIN`)

## แก้ปัญหา

| อาการ | ตรวจ |
|---|---|
| `install.ps1` บอกหา sqlcmd ไม่เจอ | ติดตั้ง sqlcmd แล้วเปิด PowerShell ใหม่ |
| ขั้นสร้างฐานข้อมูลล้ม | บัญชีที่รันต้องสร้างฐานข้อมูลและ login ได้ ถ้าใช้ SQL login ให้ใส่ `-SqlAdminUser` |
| service เริ่มแล้วไม่ตอบ | Event Viewer → Windows Logs → Application (source `Helpdesk`) ส่วนใหญ่คือที่อยู่ SQL Server หรือบัญชีเชื่อมต่อผิด |
| เปิดหน้าเว็บได้แต่ล็อกอินแล้วขึ้นว่าเชื่อมต่อไม่ได้ | `-PublicUrl` ต้องตรงกับที่อยู่ที่ผู้ใช้พิมพ์จริง (รวม http/https และพอร์ต) |
| หน้าเข้าสู่ระบบขึ้นแถบ "ระบบยังไม่ได้เชื่อมต่อฐานข้อมูล" | โปรแกรมยังไม่รู้ว่าฐานข้อมูลอยู่ที่ไหน หรือเชื่อมไม่ได้ เปิด `http://localhost:<พอร์ต>` บนเครื่องเซิร์ฟเวอร์เอง (ไม่ผ่าน proxy และไม่ใช่แอป .exe) แล้วกด "เชื่อมต่อฐานข้อมูล" หน้าต่างบอกสาเหตุ ถ้าตั้ง `Setup:Key` ไว้ ต้องใส่รหัสนั้น |
| กด "เริ่ม" แล้วบอกว่ามีบัญชี `helpdesk_...` อยู่แล้ว | ชื่อบัญชีของเครื่องนี้ซ้ำกับบัญชีที่มีอยู่ ถ้าเป็นของเครื่องนี้เองที่ติดตั้งใหม่ ให้ติ๊กยืนยันตั้งรหัสผ่านใหม่ ถ้าเป็นของเครื่องอื่น ให้ตั้งชื่ออื่นใน "ตัวเลือกเพิ่มเติม" |
| หน้าต่างบอกว่ารหัสผ่านที่บันทึกไว้อ่านไม่ได้ | คีย์ `Jwt:Key` ของเครื่องนี้เปลี่ยนไป หรือไฟล์ `database.json` มาจากเครื่องอื่น ให้กรอกรหัสผ่านและเชื่อมต่อใหม่ |
| อีเมลไม่ออก | ตั้งค่า → อีเมล (SMTP) → ส่งอีเมลทดสอบ ดูข้อความจากเมลเซิร์ฟเวอร์ |

## ใช้ Docker แทนได้ไหม

ได้ โปรแกรมเป็น ASP.NET Core ที่เชื่อม SQL Server ได้ทั้งใน Windows และ Linux มี `Dockerfile` อยู่ใน `backend/KPI.API` ให้ build image แล้วตั้งตัวแปร `Database__Provider=SqlServer`,
`ConnectionStrings__DefaultConnection`, `Jwt__Key`, `Cors__Origins__0` และสร้างผู้ดูแลคนแรกด้วย `docker run --rm -e HELPDESK_ADMIN_EMAIL=... <image> create-admin`
คู่มือนี้ทดสอบเฉพาะวิธี Windows Service
